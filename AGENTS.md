# AGENTS.md

## Cursor Cloud specific instructions

### Project overview

Eclipse Open VSX is a vendor-neutral open-source VS Code extension registry. It consists of three components:

| Component | Tech | Port | Dir |
|-----------|------|------|-----|
| **Server** | Java 25, Spring Boot 3.5, Gradle 9.3 | 8080 | `server/` |
| **Web UI** | React 18, TypeScript, Vite 7, Yarn 4.9 | 3000 | `webui/` |
| **CLI** | TypeScript, Node.js, Yarn 4.9 | — | `cli/` |

PostgreSQL 16 is the required database (runs via `docker compose --profile db up -d`). Elasticsearch is **optional** — the dev config uses DB-based search by default (`ovsx.databasesearch.enabled: true`, `ovsx.elasticsearch.enabled: false`).

### Prerequisites

- **Java 25** (Temurin) — `JAVA_HOME=/usr/lib/jvm/temurin-25-jdk-amd64`
- **Node.js >= 22** with **corepack** enabled (for Yarn 4.9.1)
- **Docker** — needed for PostgreSQL (and optionally Elasticsearch, Redis)

### Starting services

1. **PostgreSQL**: `docker compose --profile db up -d` (from repo root)
2. **Server properties** (first time only): `cd server && bash scripts/generate-properties.sh` — generates `src/dev/resources/application-ovsx.properties`. The script is idempotent; it skips if the file already exists.
3. **Server**: `cd server && JAVA_HOME=/usr/lib/jvm/temurin-25-jdk-amd64 ./gradlew assemble && JAVA_HOME=/usr/lib/jvm/temurin-25-jdk-amd64 ./gradlew runServer` — starts on port 8080. Includes `spring-boot-devtools` for hot-reload on recompile.
4. **Web UI**: `cd webui && yarn dev` — starts Vite dev server on port 3000.
5. **CLI** (optional): `cd cli && yarn prebuild && yarn build` — builds `ovsx` CLI tool at `cli/bin/ovsx`.

### Running tests

- **Server unit tests**: `cd server && JAVA_HOME=/usr/lib/jvm/temurin-25-jdk-amd64 ./gradlew unitTests` (616 tests, no Docker needed)
- **Server full tests**: `cd server && JAVA_HOME=/usr/lib/jvm/temurin-25-jdk-amd64 ./gradlew test` (includes integration tests requiring Docker/Testcontainers)
- **Web UI tests**: `cd webui && yarn test` (Mocha)
- **Web UI lint**: `cd webui && yarn lint` (ESLint)
- **CLI lint**: `cd cli && yarn lint` (ESLint)

### Non-obvious caveats

- The CLI `build` script expects `src/version.ts` generated by `prebuild`. Running `yarn build` alone in the CLI dir will fail if version.ts doesn't exist — always run `yarn prebuild` first (or `yarn prepare` which chains both).
- The `generate-properties.sh` script is idempotent: it creates `application-ovsx.properties` only if the file does not already exist. To regenerate, delete the file first.
- OAuth is configured with placeholder `client-id=none` / `client-secret=none` by default. Login won't work without real GitHub/Eclipse OAuth credentials, but the registry API and search work fine without it.
- The super admin token `super_token` is seeded automatically by the dev migration `V1_0_1__Super_user.sql`. Use it for CLI commands: `OVSX_PAT=super_token OVSX_REGISTRY_URL=http://localhost:8080 node cli/bin/ovsx create-namespace <name>`.
- Docker must be running before starting the server (PostgreSQL dependency).
- The `dockerd` daemon must be started manually in Cloud Agent environments: `sudo dockerd &>/tmp/dockerd.log &` and socket permissions fixed: `sudo chmod 666 /var/run/docker.sock`.
